# 対応マップ実装メモ

2026-09-15 / Sumradio demo2 0.2.0

## 要件と実装の対応

| 要件 | 実装 |
| --- | --- |
| 起動時の対象地域指定 | 地域名検索、地図の表示範囲、座標入力。前回設定を初期表示し、アプリ再起動時に再確認 |
| 地域内の地名照合 | 横浜市公開地点627件＋台本補足8件、追加地点JSON、確定キャッシュ、Nominatim |
| 未登録地名の自動検索 | タスク保存後の独立した非同期ジョブ。公開検索は単一キューで15秒以上の間隔 |
| 7種類の記号 | 交信から複数分類を抽出。手動登録・編集でも複数選択可能 |
| LLMに座標を作らせない | 抽出Schemaに座標欄を設けず、地点名と根拠だけを受領。外部データまたは手動確定から座標を取得 |
| 曖昧な地点 | 複数候補はピンを置かず、候補選択または手動位置の確定を待つ |
| 場所未確認・通信失敗 | 一覧に残し、手動指定と再検索を用意。音声・文字・ボード操作を継続 |
| 位置とタスクの確認 | 別操作。位置確定はタスク状態を変更しない |
| カード・根拠との連携 | カードからピン、ピンからカード詳細・元交信、同一地点の複数タスク一覧 |
| 完了・破棄 | 通常地図から非表示。履歴一覧から位置・出典・分類・根拠・状態履歴を参照 |
| 人間の訂正を保護 | タスク版、位置版、対象地域、原文版が一致した検索結果だけを保存 |
| 古いデータの読み込み | 既存JSONは地図情報なしの既定値で読み込む。過去タスクの地域を推測して付けない |

## データと責務

- `geography_models.py`: 対象範囲、地図分類、地名表現、地点候補、位置状態、入力検証。
- `geography.py`: 同梱地点・追加地点・キャッシュの照合、検索制限、公開CSVの更新。
- `storage.py`: 地域・位置・分類・操作履歴の保存。タスクの状態遷移と位置確定は独立。
- `service.py`: 交信処理と場所検索ジョブの調整。取得待ちによる音声処理の停止を避ける。
- `codex_extractor.py`: 地図情報を抽出し、原文の根拠を検証。AIが離れた文を連結した引用は、文ごとの完全一致と原文での出現順をすべて確認できた場合だけ別引用へ分割する。数字や文言の修正、一致しない文の削除は行わない。
- `static/map.js`: Leaflet地図、凡例、同一点の表示、カード・交信への導線。
- `static/geography-ui.js`: 対象地域、場所の選択・訂正、完了・破棄履歴の画面。

### 状態

既存の内部タスク状態 `candidate → open → done`、`candidate → discarded` を維持する。

位置状態は `unresolved`、`queued`、`searching`、`suggested`、`ambiguous`、`confirmed`、`not_found`、`failed`。現在の検索ジョブは待機・通信を通して `queued` と表示し、結果受信後に状態を更新する。`searching` は保存済みジョブの復元にも対応する予約状態。

1件の検索結果は `suggested` として暫定表示する。自動照合で `confirmed` にしない。人間が候補または座標を確定した場合だけ `confirmed` になる。

交信訂正時、旧版で待機中の検索を停止して未確認へ戻す。既に得た検索結果や人間の確定位置は履歴とともに残し、根拠が旧版であることを表示する。自動再検索は旧版タスクを上書きしない。

### 保存先

`SUMRADIO_DATA_DIR` 以下:

- `geography/area.json`: 前回対象地域と訓練表示。
- `geography/locations.json`: 人間が用意する追加地点一覧（任意）。
- `geography/yokohama-places.json`: 更新した公開地点一覧。同梱版を予備として利用。
- `geography/catalog-refresh.json`: 更新確認日時・ETag・Last-Modified。
- `geography/search-cache.json`: 検索結果、取得日時、最終外部検索時刻。
- `geography/confirmed-cache.json`: 人間が確定した地域・地名ごとの地点。
- `tasks/<ID>.json`: タスク本体、対象地域、分類、位置、操作履歴。

## 追加API

| API | 入力・用途 |
| --- | --- |
| `POST /api/areas/search` | `query`: 市区町村名を検索 |
| `PUT /api/area` | `name`, `bounds`（south/west/north/east）, `training` |
| `GET /api/tasks?include_discarded=true` | 破棄したタスクも含む一覧 |
| `GET /api/tasks/{id}` | タスク詳細 |
| `POST /api/tasks/{id}/location/search` | `version`: 位置を再検索 |
| `PUT /api/tasks/{id}/location` | `version` と `candidate_id`、または `name`, `lat`, `lon`。任意の `actor` |

版競合は409、範囲外座標や不正入力は422。`GET /api/state` に `active_area` と `map` を追加し、既存SSEに `area.updated`、`map.updated` を追加する。

## 利用条件と運用

Leaflet 1.9.4はライセンスとともに同梱。OSMタイルは通常のブラウザキャッシュを使用し、一括取得・先読み用の機能は追加していない。帰属表示を常時表示する。公開検索の自動利用は本アプリの単一プロセスを前提とし、複数端末や組織的な利用では管理されたサービスへ切り替える。

地図は報告内容を確認するための補助であり、施設の開設状況や入口位置を保証しない。地名・座標の出典は [地点データ](../src/sumradio/resources/README.md)、実行結果は [検証結果](../検証結果.md) を参照。
