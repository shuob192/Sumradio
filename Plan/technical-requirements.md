# Sumradio 技術要件

## 1. 目的と現在地

Sumradioは、特定小電力トランシーバーで受信した無線音声をPCへ入力し、発話単位で文字起こししてブラウザへ表示する。

確認済みの事項は次のとおり。

- 無線機からPCへ音声信号を入力できる
- Audacityで入力波形を確認できる
- 文字起こしエンジンにはWhisperを使用する

以降の技術課題は、無線音声に適した前処理、発話分割、Whisper推論、無線用語の認識補助、結果の安全な表示である。

## 2. システム構成

```text
特定小電力トランシーバー
  → 音声入力デバイス
  → 生音声の取得・保存
  → 発話区間検出
  → 周波数フィルタ・ノイズ抑制
  → Whisper推論
  → 無線用語の照合・注釈
  → イベント生成
  → SSE
  → ブラウザの時系列UI
```

主系はローカル処理とし、インターネット接続やクラウドAPIをMVPの必須条件にしない。

## 3. 音声入力要件

### 3.1 取得

- 入力デバイスを名称またはデバイスIDで明示的に選択できること
- 取得時はデバイスのネイティブサンプルレートを維持し、生音声を改変せず保存できること
- Whisper入力用には16 kHz、モノラル、16-bit PCM WAVへ変換すること
- クリッピング、無音、入力デバイス切断を検出してUIへ通知すること
- 受信開始時刻、終了時刻、入力デバイス、サンプルレートをメタデータへ記録すること

### 3.2 発話区間検出

- スケルチ音を発話開始と誤認しにくいエネルギー閾値を設定できること
- 発話冒頭を欠落させないため、検出前300 ms程度のプリロールを保持すること
- 発話終了は800〜1,200 msの無音を初期値とし、設定で変更できること
- 30秒を超える連続入力は強制的に分割すること
- 自動検出が失敗した場合、手動の録音開始・停止へ切り替えられること

## 4. 無線音声向け前処理

フィルタは常に有効化せず、同一音声を比較してCERと重要語正解率が改善した設定だけを採用する。

### 4.1 比較する前処理プロファイル

| プロファイル | 処理 | 用途 |
| --- | --- | --- |
| `raw` | リサンプルのみ | 比較基準 |
| `bandpass` | 300〜3,400 Hzの帯域通過 | 一般的な狭帯域無線音声 |
| `wide-bandpass` | 200〜3,800 Hzの帯域通過 | 子音の情報を残す比較案 |
| `bandpass-denoise` | 帯域通過＋弱いノイズ抑制 | 定常ノイズが大きい場合 |

### 4.2 フィルタ要件

- DC成分を除去すること
- 帯域通過フィルタは位相安定性を考慮し、SOS形式のButterworthなど再現可能な実装にすること
- 50 Hzまたは60 Hzのハムが実測された場合のみノッチフィルタを適用すること
- ノイズ抑制は音声を破壊しない弱い設定から開始し、強度を設定可能にすること
- 正規化後もピークを-3 dBFS以下に保ち、クリッピングさせないこと
- 生音声と処理後音声を対応付けて保存し、比較再生できること

### 4.3 採用基準

評価音声全体で、`raw` と比較して次を両方満たすプロファイルを採用する。

- CERが悪化しない
- 地名・数字・通話表の重要語正解率が改善する

改善しない場合は、リサンプルのみの `raw` を採用する。

## 5. Whisper推論要件

### 5.1 実行方式

- MVPの主系はローカルWhisper推論とする
- Pythonから扱いやすく高速化しやすい `faster-whisper` を第一候補とする
- GPUが利用できる場合はFP16、CPUの場合はINT8を候補として実測比較する
- モデルは開催前にダウンロードし、オフラインで起動できること

### 5.2 モデル選定

同じ評価セットで `small`、`medium`、`large-v3` を比較する。次の条件を満たす最大のモデルを採用する。

- PTT解放から画面表示までp95で5秒以内
- デモ5発話を連続処理してメモリ不足やクラッシュがない
- 重要語正解率が80%以上

`large-v3` が時間要件を満たさない場合は `medium`、さらに満たさない場合は `small` へ縮退する。

### 5.3 初期推論設定

- `language="ja"`
- `task="transcribe"`
- `temperature=0`
- `beam_size=5`
- 発話ごとの文脈混入を避けるため `condition_on_previous_text=false`
- 文字起こし区間の確認用にセグメント時刻を取得する
- `avg_logprob`、`no_speech_prob`、処理時間を記録する

これらは固定値ではなく、評価セットで変更前後を比較して確定する。

### 5.4 ハルシネーション対策

- 無音またはスケルチのみの区間を文字起こし結果として登録しない
- 同じ語句の異常な繰り返しを検出する
- 短すぎる発話や低い平均log probabilityを「要確認」にする
- 前の発話を次の発話へ自動継承しない
- 不明箇所をLLMで推測補完しない

## 6. 無線用語・通話表への対応

### 6.1 用語辞書

無線用語はコードへ直書きせず、`config/radio_terms.yaml` で管理する。

```yaml
nato_phonetic:
  A: [アルファ, アルファー]
  B: [ブラボー]
  C: [チャーリー]
japanese_phonetic:
  ア: [朝日のア]
  イ: [いろはのイ]
domain_terms:
  - 青葉避難所
  - 調査一班
```

本番実装では欧文通話表A〜Zと、デモで使用する和文通話表・部隊符号・架空地名を登録する。

### 6.2 認識補助

- Whisperの初期プロンプトまたはhotwordsへ辞書語を渡す
- 日本語であること、句読点、数字表記の例をプロンプトへ含める
- 一つの長いプロンプトではなく、デモに必要な語だけを渡す
- プロンプトなし／ありで同じ評価音声を比較する

### 6.3 正規化

- Whisperの出力を `raw_text` として必ず保持する
- 辞書に一致した語は削除・置換せず、`A（アルファ）` のような注釈候補を `normalized_text` に生成する
- 「アルファ」という一般語を無条件に `A` へ置換しない
- 通話表として連続して読まれた場合や、明示的な符号読みの文脈でのみ変換候補を提示する
- 地名、数字、否定語の自動訂正は行わず、人間の確認を必要とする

## 7. データ要件

文字起こしイベントは少なくとも次の情報を持つ。

```json
{
  "id": "01J...",
  "received_at": "2026-09-07T09:15:30+09:00",
  "raw_text": "訓練、青葉避難所、要支援者十五名",
  "normalized_text": "訓練、青葉避難所、要支援者15名",
  "status": "needs_review",
  "source": "live_radio",
  "model": "medium",
  "preprocess_profile": "bandpass",
  "avg_logprob": -0.42,
  "no_speech_prob": 0.03,
  "latency_ms": 2400,
  "audio_ref": "local:event-id.wav",
  "glossary_hits": ["青葉避難所", "15名"]
}
```

- `status`: `recording | processing | needs_review | confirmed | failed`
- `source`: `live_radio | recorded_radio | mock`
- 生音声、処理後音声、原文、正規化文を同じIDで追跡できること
- 人間の訂正は、訂正文・修正者・修正時刻を別レコードで残すこと

## 8. UI・配信要件

- FastAPIからSSEで文字起こしイベントを配信する
- タイムラインには受信時刻、原文、正規化候補、処理状態、遅延を表示する
- 全結果を初期状態「AI文字起こし・要確認」とする
- 地名、人数、時刻、否定語、通話表を色とラベルの両方で強調する
- 「確認済み」への変更操作を提供する
- 入力デバイス切断、推論失敗、無音、処理遅延を明示する
- 画面上部に「デモ／訓練」「対応判断に単独使用しない」を常時表示する

## 9. 性能・品質要件

- PTT解放から画面表示までp50で3秒以内、p95で5秒以内
- 既定台本5発話を連続処理し、クラッシュしない
- 地名・人数・時刻・否定語・通話表の重要語正解率80%以上
- 音声区間の開始欠落・終了切断を合わせて10%未満
- 同じ構成でデモを3回連続成功できる
- 生音声と処理後音声を切り替えて再評価できる

## 10. 評価要件

### 10.1 評価セット

最低30発話を用意する。

- 通常の無線音声10発話
- ノイズを含む音声5発話
- 音切れを含む音声5発話
- 欧文・和文通話表を含む音声5発話
- 地名、人数、時刻、否定表現を含む音声5発話

すべてに正解文字列と重要語スロットを付与する。

### 10.2 比較実験

次の組み合わせを同一データで比較し、結果をCSVまたはJSONへ保存する。

- 前処理: `raw` / `bandpass` / `wide-bandpass` / `bandpass-denoise`
- モデル: `small` / `medium` / `large-v3`
- 用語補助: なし / 初期プロンプトまたはhotwordsあり

### 10.3 指標

- CERと参考値としてのWER
- 重要語スロット正解率
- 発話区切り成功率
- p50・p95推論時間とE2E遅延
- 無音・ノイズ区間での誤文字起こし率

## 11. テスト要件

- 周波数フィルタが指定帯域外を減衰させる単体テスト
- リサンプル後のサンプルレート、チャンネル数、PCM形式の検証
- VADのプリロール、終了無音、最大長の境界テスト
- 用語辞書の読み込みと、原文を破壊しない正規化テスト
- 無音、ノイズ、空のWhisper結果、推論例外のテスト
- SSE再接続とイベント順序の統合テスト
- 実機5発話を使ったE2Eテスト

## 12. フォールバック

1. 自動VADが失敗したら、手動開始・停止へ切り替える
2. 採用モデルが遅ければ、`large-v3` → `medium` → `small` の順に縮退する
3. ノイズ抑制で精度が低下したら、`bandpass` または `raw` へ戻す
4. PCへの直接入力が不安定なら、無線機スピーカーをUSBマイクで収音する
5. ライブ処理が失敗したら、事前録音音声をローカルWhisperへ入力する
6. 推論が復旧しなければ、保存済み結果の時系列再生または画面録画を使用する
