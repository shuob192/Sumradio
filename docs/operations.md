# デモ運用・フォールバック

## 90秒デモ

1. 0〜10秒: 「デモ／訓練」「対応判断に単独使用しない」を示す。入力経路を説明する。
2. 10〜20秒: 「訓練、本部、本部、こちら調査一班」。暫定字幕を確認。
3. 20〜30秒: 「訓練、青葉避難所、要支援者15名、負傷者2名」。地名・人数のラベルを確認。
4. 30〜45秒: 「訓練、青葉避難所へ飲料水15箱を手配願う」。候補の内容を確認し、未対応へ移す。
5. 45〜60秒: 「訓練、青葉避難所への飲料水の手配、完了」。自動では消えないことを示し、人間が根拠を確認して対応済みへ。
6. 60〜80秒: 「訓練、若葉公園、道路は未確認、車両は通行できない」。否定語を確認。実際の録音では原音を再生し、誤認識があれば訂正する。
7. 80〜90秒: 交信履歴と対応ボードを示す。「人間の確認を支える第二の記録係」と説明。

文字列・地名・部隊はデモ用。保存済み台本を使った場合は音声がなく、ASRが実行されていないことを明示する。

## 切替手順

| 状況 | 操作 |
| --- | --- |
| 自動区切り失敗 | 「停止・録音途中を破棄」→手動モード→入力開始→手動録音開始／発話終了 |
| 音声入力切断 | 入力停止→デバイス再取得→再開。復旧しなければ事前録音WAVを認識 |
| 認識が10秒を超える | 入力を停止。`.env` のモデルを比較結果に基づき変更し再起動 |
| モデルの縮退 | `large-v3-turbo` → `large-v3` → `medium` → `small`。速さは実測して選択 |
| フィルタで精度低下 | `.env` の `SUMRADIO_PROFILE=raw` にして再起動 |
| タスク抽出不調 | `SUMRADIO_AUTO_EXTRACT=false` にして再起動。交信から手動作成 |
| ASRが復旧しない | 音声入力停止→「保存済み台本を再生」（レベル3） |
| アプリ自体が復旧しない | チームが事前収録した画面録画を再生（レベル4） |

ピッチ中の再試行は1回まで、復旧に60秒以上かかる場合は画面録画へ切り替える。録画は実機で正常動作を確認した後にチームが作成する。

## 録音の管理

- 参加者から録音・ローカル処理・デモ利用の同意を得る。
- 実際の運用交信や第三者の通信は入力しない。各交信を「訓練」で始める。
- 第三者の交信が入った場合は「停止・録音途中を破棄」。現在のメモリ内発話は保存しない。
- すでに発話終了して認識キューへ入った発話は処理・保存が続く。その場合はデモを中止し、保管担当者が対象データを確認・削除する。
- 音声をキューへ渡した時点でローカル保存対象になる。入力待機中の音声は永続保存しない。
- 本番と同じケーブル・レベル・デバイスで10分録音し、冒頭欠落・音割れ・切断を点検する。
- 終了後の削除担当者・期限をチームで記録し、サーバーを停止してデータを削除する。SQLiteのWAL/SHMを含む `data/` 全体が対象。

## 既知の制約

- エネルギーによる発話検出は意味上の音声／スケルチ識別ではない。持続ノイズでは誤区切りが起こり得る。
- 暫定字幕は直近5〜8秒窓の結果。重なる2結果の共通接頭辞を安定部分とし、認識途中も別表示する。長い発話全体は発話終了後の確定字幕で表示。
- 暫定／確定それぞれ1ワーカー。暫定推論が遅いと更新頻度は設定より低下する。確定認識の待ち行列は最大4件で、満杯時は入力を停止し画面に通知する。
- モデル初回ロードを含むレイテンシ、CPU/CUDA性能、GPUメモリは実測が必要。自動モデル変更はせず設定で切り替える。
- 保存済み台本モードはテキスト再生。任意の保存済み音声付きセッションの丸ごとインポートは未実装。
- 全件要確認で開始。辞書にない地名・担当・対象は抽出できないことがあり、否定や訂正文では提案を抑制する。
- 修正後テキストから自動再抽出はしない。既存候補と重要語ラベルは元のASR原文に基づくため人間が編集する。
- SQLite/outbox/音声の自動期限削除はない。長期間連続運用向けの容量管理は未実装。
- 1台のローカルPC向け。ユーザー認証や真正性保証は提供しない。
