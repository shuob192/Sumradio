# Sumradio

マイクで受けた無線交信を文字にし、人間が確認する対応ボードと地図へつなぐローカルアプリです。

「架空地名・青葉地区（既存10交信）」と「実在地名・東京都内（追加3交信）」を切り替えられます。どちらも**訓練：状況は架空**です。台本の文章を字幕や抽出結果に埋め込む機能、録音ファイルを入力する機能はありません。

## このMacで起動する

このフォルダで依存関係・画面の構築・Whisper mediumの準備が済んでいる場合：

```sh
uv run --frozen sumradio serve
```

[Sumradioを開く](http://127.0.0.1:8765)。終了は起動したターミナルで Control + C。`Sumradioを起動.command` のダブルクリックでも起動できます。同じ保存先では二重起動しません。

録音は画面で「録音を開始」を押してから始まります。入力マイクを選び、macOSの「プライバシーとセキュリティ → マイク」で、起動元アプリ（ターミナル等）へのアクセスを許可してください。ブラウザーではなくPythonの音声処理がマイクを使います。iPhoneのマイクが見える場合もあるため、Mac内蔵マイクを使うときは明示的に選択します。

## 初回セットアップ

対象はApple Silicon Mac、Python 3.12、Node.js 22.12以降、uv、pnpm 11.19.0です。このリポジトリを残した状態で使うソース配布版です。単独のPython wheelやmacOSアプリバンドルとしての配布は対象外です。

```sh
uv python install 3.12
uv sync --frozen
cd frontend
pnpm install --frozen-lockfile
pnpm build
cd ..
uv run --frozen sumradio prepare-model
uv run --frozen sumradio doctor
uv run --frozen sumradio serve
```

`prepare-model` は初回だけモデルをダウンロードするため通信と空き容量が必要です。通常起動時にはダウンロードせず、保存済みのmediumをCPU・INT8で読み込みます。モデル未準備でも録音・保存・手動操作はできますが、文字起こしは失敗表示になります。

Codex CLIへ事前にChatGPTアカウントでログインしてください。CLIをPATHから検出し、なければこのMacのCodexアプリ同梱CLIを確認します。別の導入先は `SUMRADIO_CODEX_BIN` で指定できます。

```sh
codex login
codex login status
```

Sumradio専用のAPIキーは使いません。タスク抽出はCLIの認証と利用枠を使用します。`doctor` がCLIの版・ログイン状態・マイク一覧・通話表の読み込み数を表示します。CLI実行仕様は[公式の非対話実行ドキュメント](https://learn.chatgpt.com/docs/non-interactive-mode)を参照してください。

## 操作

1. 開始画面で必要なら「対象地域を指定」の都道府県・市区町村を入力し、「架空地名・青葉地区」「実在地名・東京都内」「通常利用」のいずれかを選択。選択のたびに新しい実施回を作成します。続きは「過去の実施回」から開きます。架空デモは地域指定の対象外で、青葉地区固定です。
2. 操作者名・入力マイクを確認して録音を開始。直前0.5秒を保持し、連続無音5秒で交信を確定します。短い無音は同じ交信として継続します。「手動で区切る」の場合は録音停止で確定します。
3. 発話中は暫定字幕、確定後は時刻付きの交信記録を表示します。暫定字幕は直近20秒を対象に約1.5秒ごとに要求しますが、処理中の古い要求は間引きます。確定認識は録音全体が対象です。
4. AIの整理を待たずに原文・原音を確認できます。誤認識は「訂正」で直します。原文・訂正履歴・訂正前の候補は残ります。訂正前の候補は自動で消えないため、根拠を確認して編集または破棄してください。
5. 候補の内容・数量・根拠・種別を確認。場所が一致した場合も「この位置を確認」を人間が操作します。不明な入口などは手動指定できます。手動指定時は地図をクリックするか緯度経度を入力します。
6. 「承認して未対応へ」で対応対象にします。不要な候補は「破棄」。要請への対応後、または状況確認の判断後に「対応済みにする」を操作します。AIは状態を変更しません。
7. 録音を停止して実施回を切り替えます。抽出が進行中でも元の実施回へ保存されます。複数ブラウザーを開いた場合も、録音はアプリ全体で1系統です。

手動登録も「タスク候補」から始まります。編集時には理由を残してください。他の更新と競合したら最新状態を読み直してから再操作します。専用のタスク統合・数量の自動合算はありません。完了報告と重複の可能性は確認事項として表示します。

## 聞き取りに誤りがある場合

誤認識を含んでいても、要請が読み取れる場合は「聞き取り要確認」の候補として整理します。品目を特定できなければ品目の確認を含む要請候補にし、数量・地名・否定を推測で確定しません。意味の仮説は「聞き取りの確認候補」に原文と分けて表示します。原音と照合し、必要なら「訂正」またはタスク編集を行ってください。

地名の解釈候補が対象地域内の登録地点1件と一致する場合は、確認欄に **「上野恩賜公園」として承認・地図表示** のようなボタンが出ます。表示名・地域・代表点の注記を確認して1回押すと、そのタスクの場所が確定し、地図にピンが出ます。交信の再抽出や座標入力は不要で、過去の保存済み交信にも対応します。

これは**地名の解釈と位置だけの承認**です。原文・数量・根拠・タスクの状態は変更しません。「タスク候補」のままならピンも候補の破線表示です。内容全体を確認して「未対応」へ移す操作は別に行ってください。場所の確認者・時刻・採用した解釈と原文は履歴へ保存します。

未登録地名、同名候補が複数ある場合、地域の矛盾、未登録の入口、複数の場所が含まれ解釈とタスクの対応が曖昧な場合は、ワンタッチの候補を出しません。従来の手動位置指定・訂正を使ってください。外部地名検索は行わず、公園の代表点を詳細な現場位置には置き換えません。

AIには原文の箇所IDを選ばせ、引用文・交信ID・版番号はアプリが原文から付与します。AIが誤字を解釈した文章を原文引用へ混ぜることによる失敗を防ぎます。不正JSON、存在しない箇所ID、通信失敗は引き続き拒否し、確認を通さず登録することはありません。これは音声認識の精度改善や、すべての誤認識を正しく推定できることの保証ではありません。

## 地図とデモ

### 起動時の対象地域

「都道府県」で東京都、「市区町村」で台東区などを指定できます。市区町村を空欄にすると都道府県全体、都道府県を「指定しない」にすると従来どおりです。市区町村は手入力でき、登録地点に含まれる名前が入力候補に出ます。全国の市区町村一覧・行政境界データを同梱した機能ではなく、自由入力の自治体の実在性までは検証しません。

指定地域は実施回の設定として保存し、見出しと過去の実施回にも表示します。過去の回を開いても、新規作成用の入力でその回の地域を上書きしません。地域を変更する場合は録音停止後に「実施回を切り替え」から新しい回を作ります。既存の地域指定なしの記録もそのまま開けます。

- 地名候補は位置マスター・位置キャッシュの自治体名で絞ります。台東区を指定すると、上野公園は候補にできますが、渋谷区の代々木公園は自動候補にしません。地域が複数区にまたがる橋では、登録されたいずれかの区と一致すれば候補になります。
- 地域と交信の自治体が矛盾する場合は「場所未確認」にします。交信・タスク自体は捨てません。必要なら人間が場所を手動指定できます。
- 初期地図は、指定地域内に登録地点がある場合、その地点が見える範囲へ移動します。登録地点がない地域の地図中心や行政境界を外部検索で補完することはありません。
- 通常利用で外部検索を設定している場合のみ、指定地域を検索条件に付加し、返された住所情報でも一致を検証します。両デモでは地域を指定しても外部地名検索は0件です。
- 地域は検索条件であり、発言内容ではありません。Whisperの補助文やCodexの入力へ追加せず、原文・根拠引用・交信から抽出した自治体を設定地域で書き換えません。

実在デモの3交信をすべて実施する場合は「東京都」だけを指定するか、地域指定なしにしてください。台東区まで絞った場合、R02・R03の位置はその地域の候補から外れます。

### 登録地点と表示

- 実在地点は上野恩賜公園、代々木公園、永代橋。名称・自治体・読み・別名・座標・出典・確認日を `data/profiles/tokyo.json` に同梱しています。
- 公園・橋の点は**代表点であり、現場や入口の正確な位置ではありません**。未登録の詳細地点を公園全体の座標で自動補完しません。
- 両デモでは外部の地名検索をコード側でも禁止します。正式名・登録別名が一致しない場合、自治体が矛盾する場合、複数候補の場合は人間の確認対象です。
- 架空地点の座標は地図表示用の訓練設定です。背景に実在の地図が表示されても、その場所に被害や施設が実在することを意味しません。
- 🩸負傷者、🚑救助・搬送、🩺体調不良・医療、💧飲料水・給水、×通行障害、🔥火災・煙、🌊浸水・冠水、🏚️建物被害、📡通信障害、🔍行方不明・安否確認、🚻トイレ・衛生、📦物資、🏃避難支援、⚡停電・電源、!その他の15分類です。血のマークは出血量や重症度を示しません。
- 負傷者の搬送なら🩸と🚑を併記します。同じ位置の全タスクから最大3記号を表示し、さらに分類があると`+N`が付きます。タスク件数は別のバッジです。ピンを開くと全分類と個別タスクを確認できます。記号の並び順は対応の優先順位ではありません。
- 記号は「手動登録」やタスクの「編集」で複数選択できます。過去の記録を勝手に再分類しないため、以前`rescue`だった負傷者タスクに血のマークを足したい場合は「負傷者」を選んで保存してください。
- 候補と未対応だけが通常地図に表示され、対応済み・破棄は履歴に残ります。破線はタスクまたは位置が未確認であることを表します。

背景はOpenStreetMapです。ブラウザーの通常のHTTPキャッシュを利用し、画面で必要なタイルだけ取得します。未取得タイルには通信が必要で、完全なオフライン地図は同梱しません。取得失敗時も一覧・保存済み位置・手動操作は使えます。[タイル利用方針](https://operations.osmfoundation.org/policies/tiles/)、[Nominatim利用方針](https://operations.osmfoundation.org/policies/nominatim/)、[出典・ライセンス](https://www.openstreetmap.org/copyright)に従います。

台本： [架空10交信](無線交信台本.md) ／ [実在3交信](無線交信台本_実在地名.md)。90秒デモは架空01・02・03と実在R01・R02・R03、時間が足りなければ各先頭2交信。各版3回を測定し、承認後は未対応のまま残します。完了とピン消去は別の操作テストで確認します。

## 設定

環境変数を設定して起動します。`.env` の自動読み込みはありません。

| 変数 | 既定値／用途 |
|---|---|
| `SUMRADIO_DATA_DIR` | `~/Library/Application Support/Sumradio`。保存先 |
| `SUMRADIO_MODEL_DIR` | 保存先内の`models`。別の検証保存先とモデルを共有する場合に指定 |
| `SUMRADIO_CODEX_BIN` | PATHのCLI、またはアプリ同梱CLI |
| `SUMRADIO_CODEX_MODEL` | `gpt-5.6-luna`。利用可能なCLIモデル名に変更可能 |
| `SUMRADIO_WHISPER_COMPUTE` | `int8`。モデルはmedium、デバイスはCPU |
| `SUMRADIO_WHISPER_THREADS` | `4`。認識処理1件あたり。確定と処理中の暫定字幕が重なる場合は最大2件 |
| `SUMRADIO_WHISPER_BEAM` | `1`。変更後は認識品質と時間を再測定 |
| `SUMRADIO_VOICE_THRESHOLD` | `0.012`。RMS音量の区切り判定値。音量メーターを見て調整 |
| `SUMRADIO_PORT` | `8765`。待ち受けアドレスは`127.0.0.1`固定 |
| `SUMRADIO_TILE_URL` | `https://tile.openstreetmap.org/{z}/{x}/{y}.png` |
| `SUMRADIO_GEOCODER_URL` | 空＝外部地名検索しない。通常利用専用のNominatim互換URL |
| `SUMRADIO_GEOCODER_AGENT` | 空。通常利用の外部検索にはアプリ名・連絡先等の識別情報が必須 |

通常利用プロファイルでは位置マスター→人間が確認した位置キャッシュ→設定された外部検索の順に解決します。公開検索は単一処理・1秒に1件以下・結果をディスクへキャッシュ。検索へ送るのは地名と自治体だけです。公開サービスに機密の運用地点を送らず、機密性の高い運用では登録地点や自己ホストサービスを使用してください。

確定認識と暫定字幕は別々に処理し、処理中の字幕が終わるのを待たずに確定認識を開始します。確定処理が待機・実行中なら新たな暫定認識は開始しません。両方とも同じmediumモデルを使用し、確定時は録音全体を認識します。モデルの重みは共有しますが、同時処理のため作業メモリが増えます。4スレッドの既定値はこのMacの保存音声比較で選びました。他の機器では時間と認識内容を再測定してください。

## 保存と復旧

```text
保存先/
  models/                    Whisperモデル
  location-cache/<profile>.json
  geocoder-cache/             通常利用の検索結果
  runs/<run_id>/
    state.json               正本：交信・タスク・操作履歴・処理状態・版・計測
    comm_<uuid>.md            原文と訂正、受信時刻、原音へのリンク
    comm_<uuid>.json          交信と整理結果の派生出力
    tasks.json               タスクの派生出力
    audio/<comm_id>-original.wav
    audio/<comm_id>-16k.wav
```

JSONは一時ファイルへの書き込み・同期後に置き換えます。実施回の`state.json`が保存確定点で、Markdownと個別JSONは起動時に再生成します。複数ファイルへの書き込み途中で停止しても同じ候補を重ねて登録しません。確定した場所のキャッシュも正本から修復します。録音中に強制終了した場合は、保存されていたWAVを再認識します。OS障害などで最後の未同期音声が失われる可能性は残ります。

バックアップは録音停止・アプリ終了後、保存先全体をコピーしてください。復元はそのコピーを `SUMRADIO_DATA_DIR` に指定して起動します。`state.json` を残し、派生JSONだけを書き換えないでください。読めない正本は起動状態の警告に表示し、上書きしません。データの削除・公開・外部転送は自動で行いません。

WAVはPC内に保存されますが、タスク整理時の文字起こし、通話表、必要な関連タスクの情報はCodex経由でクラウドへ送信されます。認証情報や録音フォルダ全体は渡しません。ローカルのみの待ち受けは、同じPCの他の利用者・プログラムからのアクセスを防ぐ認証機能ではありません。共有端末での運用には別途アクセス制御が必要です。

## 検証

```sh
uv run --frozen ruff check sumradio tests scripts
uv run --frozen pytest -q
uv run --frozen python scripts/export_schema.py
cd frontend
pnpm exec openapi-typescript ../schemas/openapi.json -o src/api-types.ts
pnpm build
pnpm exec playwright install chromium
pnpm test
cd ..
```

自動テストはマイクやクラウドがなくても実行できます。音声波形やCLIを模擬したテストは、実音声の認識精度を証明するものではありません。画面テスト用の記録は `.sumradio-data/e2e-*` に分離します。

実際のCLIで台本テキストを整理する確認（クラウド通信・利用枠を使用）：

```sh
uv run --frozen python scripts/check_live.py --case all --output reports/live-extraction.json
```

これは保存済みテキストの検証で、マイク受入確認ではありません。`valid_json_and_evidence` は形式・参照・引用の検証結果であり、内容の正しさを保証しません。

実機検証は台本をマイクで読み、原音・字幕・数量・人名/地名・分類・根拠を照合します。[検証手順](検証手順.md)に従い、重要語一致率80%以上、無音待ちを除いた確定文字の表示中央値3秒以内・95%点5秒以内を目標として実測してください。達成を前提にしません。[検証記録](reports/検証記録.md)に実施条件と未検証項目を記載します。

## 実装の構成

`sumradio/audio.py`＝マイク・区切り・Whisper、`extraction.py`＝CLI・JSON検証、`service.py`＝処理キューと人間操作、`storage.py`＝原子的保存、`locations.py`＝位置解決、`app.py`＝ローカルAPI、`frontend/src/main.tsx`＝画面です。API仕様は `schemas/openapi.json`、CLIの出力形式は `schemas/extraction.json`（根拠は`source_id`）。保存・画面配信時には根拠を原文の引用・交信ID・対象版へ展開します。起動中は `/docs` でも参照できます。

依存関係の確定版は `uv.lock` と `frontend/pnpm-lock.yaml`。要件は [要件定義](要件定義.md)、方式は [技術仕様](技術仕様.md)、開発ルールは [AGENTS.md](AGENTS.md) が基準です。
