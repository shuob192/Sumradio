# Sumradio 受入検証

## 記録する条件

実施日、Mac機種・メモリ、macOS、マイク名、読み上げ/無線機スピーカー、距離、室内雑音、ネットワーク、Whisper設定、CLI版・モデルを記録します。合成波形・保存テキスト・実際の読み上げを区別してください。訓練内容とクラウド文字処理への同意を確認し、実際の災害情報と混同しないでください。

## マイクでの全交信確認

1. 新しい架空デモ実施回で01〜10、別の実在デモ実施回でR01〜R03を、本文どおりマイクから読み上げる。
2. 各交信間で5秒以上黙る。5秒未満の間では交信が分割されないことも確認する。
3. 元WAVと16 kHzモノラルWAVが両方保存されることを確認。音声を再生して、長い交信の冒頭と末尾が確定文字に残ることを照合する。
4. 地名、要請内容、数量・単位、人数と内訳、否定・未確認の表現を原音と比較する。測定前に重要語を定め、「一致した重要語数 / 対象重要語数 × 100」で記録する。訂正後の文章で認識精度を計算しない。
5. R01は飲料水15箱・水滴、R02は負傷者3名と内訳2/1・救助、R03は通行障害・バツ印。入口・橋の側など不明な詳細を推測していないことを確認する。
6. 代表点の注記を確認して位置を確定し、候補を未対応へ承認する。画面・保存ファイル・再起動後の状態が一致することを確認する。

通話表の追加入力は「符号は朝日のあ」「符号はアルファ」、負例は「ホテルへ向かっています」「アルファ波についての一般連絡」。前者の解釈がア/Aになり、後者を勝手に文字へ変換しないことを確認します。「青葉避難所に負傷者3名」は状況確認候補。「未完了」「保留」「到着は未確認」を完了としないことも確認します。

## 計測値

交信JSONの `metrics` に保存します。画面が表示されている間だけ描画後の時刻を計測し、過去の記録を開いた時間は混ぜません。表示直前に版が変わった場合など、画面計測値が欠測することがあります。欠測は0秒とせず、別記して再測定してください。

| 項目 | 意味 |
|---|---|
| `segmentation` | automatic / manual / interrupted を分ける |
| `finalized_at_epoch - speech_ended_at_epoch` | 無音待ち等。自動区切りはおよそ5秒 |
| `speech_queue_wait_ms` | 区切り確定→確定認識キューの処理開始。暫定字幕の待ち時間や確定処理の滞留を調べる |
| `speech_preparation_ms` | 元WAVの読み込み・16 kHz変換・認識用WAVの保存時間 |
| `recognition_ms` | 確定認識自体の時間 |
| `final_text_delay_ms` | 区切り確定→サーバー側で確定文字ができるまで。画面表示時間とは区別 |
| `final_display_delay_ms` | 区切り確定→ブラウザー描画後。目標：中央値3000ms以内、95%点5000ms以内 |
| `speech_to_display_ms` | 実際の発話終了→確定文字表示。無音待ちを含む |
| `subtitle_samples` / `subtitle_total_display_ms` | 暫定字幕の表示遅延の件数と合計。合計÷件数が平均 |
| `subtitle_max_display_ms` | 暫定字幕の最大表示遅延 |
| `codex_ms` | CLI呼び出しから検証済み整理結果まで |
| `speech_to_tasks_ms` | 発話終了→整理完了まで。待機・無音・認識・CLIを含む |

モデル準備直後の初回と、その後の測定を分けます。少数標本での95%点は参考値です。バックグラウンドタブや画面を閉じた状態で画面表示遅延を測定しません。CPU・INT8のmediumが目標に届かない場合、数値を記録し、モデルを勝手に小型へ変更して達成扱いにしません。

### 保存音声を使う内部性能比較（受入試験とは別）

`scripts/benchmark_speech.py` は保存済みWAVを同じmediumで再認識し、CPUスレッド数とタイムスタンプ生成の有無を比較します。`scripts/benchmark_speech_queue.py` は20秒を超える録音で、暫定認識が始まった直後の手動停止を模擬し、実装の認識キューを測定します。後者の記録は専用の一時フォルダーに作成し、元の実施回・原音・タスクを変更しません。どちらも外部へ音声を送信せず、マイクやCodexは起動しません。

```sh
uv run --frozen python scripts/benchmark_speech.py /path/to/recorded-original.wav --threads 8,4 --rounds 2 --output reports/new-speech-comparison.json
uv run --frozen python scripts/benchmark_speech_queue.py /path/to/recorded-original.wav --threads 4 --rounds 2 --output reports/new-queue-comparison.json
```

出力先には未使用のファイル名を指定します。音声のハッシュ、条件、認識文、時間を残します。元音声の台本はモデルへ与えません。認識文が変化した場合は原音と照合し、速度だけで採用しないでください。これは実際のマイク入力・無音検出・画面表示の再確認に代わるものではありません。ライブ録音中の同時実行は処理負荷と測定値へ影響するので避けてください。

## 操作・障害確認

- 同じ場所の複数タスクをピンから個別に選択。候補承認と場所確定は別操作。完了/破棄時にピンだけが消え、履歴に内容と場所が残る。
- 同じ要請を再度読み、既存数量・状態が自動で変わらないことを確認。完了報告も既存タスクへの確認事項として扱い、人間が完了を操作する。
- 抽出中に録音を停止し別デモへ移る。元の実施回だけに抽出結果が届く。再起動して両方の記録を再開する。
- 抽出中に訂正し、古い版の結果が新しい候補として登録されないことを確認。再試行を重ねても同じ交信・版の候補が二重登録されない。
- 地点正式名、登録別名、自治体の矛盾、同名の複数候補、未登録の地名・入口を確認。両デモの地名検索リクエストは0件（背景タイルは地名検索とは別）。
- ネットワーク切断後も録音、ローカル文字認識、手動登録、編集を継続できる。CLI失敗を表示し、復旧後に手動で再試行できる。背景地図が失敗しても一覧は操作できる。
- 不正JSON・引用不一致・上限超過・60秒タイムアウトは模擬CLIテストでも確認する。模擬試験を実通信断の試験と表記しない。

自動テスト結果、保存テキストのCLI結果、マイクでの結果、未実施の項目を分けて `reports/検証記録.md` にまとめます。
